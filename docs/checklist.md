Linkord セキュリティチェックリスト

0. 最優先：公開前の基本確認

- [ ] ".env" / Secrets がGitHubに公開されていない
- [ ] Discord Bot TokenがGitHubに存在しない
- [ ] OAuth Client Secretがフロントエンドに含まれていない
- [ ] DBパスワードがフロントエンドに含まれていない
- [ ] VPSのSSH秘密鍵がリポジトリに存在しない
- [ ] APIキー・Webhook URL・署名秘密鍵がフロントJSに含まれていない
- [ ] ソースマップ（".map"）から秘密情報が漏れていない
- [ ] 本番用デバッグ機能が無効になっている

1. 認証

- [ ] パスワードを保存する場合はArgon2id等の安全なパスワードハッシュを使用
- [ ] パスワードをログに出さない
- [ ] ログイン試行回数を制限
- [ ] ブルートフォース対策がある
- [ ] セッションCookieに "Secure" を設定
- [ ] セッションCookieに "HttpOnly" を設定
- [ ] "SameSite" を適切に設定
- [ ] ログアウト時にセッションを無効化
- [ ] パスワードリセット用トークンを推測できない
- [ ] パスワードリセットトークンに有効期限がある

2. Discord OAuth

- [ ] Client Secretをフロントに置いていない
- [ ] OAuthの"state"を検証してCSRF対策
- [ ] Redirect URIを固定・許可リスト化
- [ ] 不要なOAuth Scopeを要求しない
- [ ] Access Tokenをログに出さない
- [ ] Refresh Tokenを保存する場合は暗号化
- [ ] トークン漏洩時に失効できる仕組みがある
- [ ] OAuth Callbackを直接叩かれても不正ログインできない

3. API認可

最重要

- [ ] 「ログイン済み」だけでAPI操作を許可していない
- [ ] 自分以外のプロフィールを勝手に変更できない
- [ ] 自分以外のメディアを削除できない
- [ ] URLのIDを書き換えるだけで他ユーザーのデータを取得できない
- [ ] 他ユーザーの設定を変更できない
- [ ] 管理者APIを一般ユーザーが呼び出せない
- [ ] APIごとに権限チェックを実装している
- [ ] IDOR/BOLAを全APIで確認

特に確認する場所

- [ ] "/users/*"
- [ ] "/profiles/*"
- [ ] "/media/*"
- [ ] "/storage/*"
- [ ] "/admin/*"
- [ ] Discord関連API
- [ ] プロフィール編集API
- [ ] サーバー掲載・削除API

4. 入力値

- [ ] ユーザー入力を信用しない
- [ ] JSON入力をバリデーション
- [ ] 文字数制限
- [ ] 数値の範囲チェック
- [ ] ID形式のチェック
- [ ] URL形式のチェック
- [ ] 想定外のフィールドを受け付けない
- [ ] SQL Injection対策
- [ ] Command Injection対策
- [ ] SSRF対策
- [ ] XSS対策

5. XSS

- [ ] プロフィール名でHTML/JSを実行できない
- [ ] 自己紹介欄でHTML/JSを実行できない
- [ ] SNSリンク欄でJavaScript URLを登録できない
- [ ] Minecraft関連データをHTMLとして解釈しない
- [ ] Discord情報をそのままHTMLに挿入しない
- [ ] "innerHTML" の使用箇所を確認
- [ ] ReactのdangerouslySetInnerHTML使用箇所を確認
- [ ] Content-Security-Policyを検討

6. ファイルアップロード

Linkordでは特に重要。

- [ ] アップロードサイズ上限
- [ ] ファイル形式の許可リスト
- [ ] 拡張子だけで安全性を判断しない
- [ ] MIME Typeだけでも判断しない
- [ ] ファイル名をユーザー入力のまま保存しない
- [ ] パストラバーサル対策
- [ ] 実行可能ファイルをアップロードできない
- [ ] アップロードファイルをWebサーバー上で実行できない
- [ ] SVGアップロード時のXSS対策
- [ ] 動画・音声ファイルのサイズ制限
- [ ] 他人のファイルを削除できない
- [ ] 他人のファイルURLを推測して取得できない
- [ ] 削除APIに認可チェックがある
- [ ] ファイル保存先をアプリ本体から可能なら分離

7. パストラバーサル

特に "media.py" / "storage.py" / "admin.py" を重点確認。

- [ ] "../" を利用して別ディレクトリへアクセスできない
- [ ] 絶対パスを指定できない
- [ ] URLエンコードされた "../" も防ぐ
- [ ] Windows形式パスも想定
- [ ] シンボリックリンク経由の脱出を防ぐ
- [ ] 削除対象パスをユーザー入力から直接生成していない

8. レート制限

- [ ] ログインAPI
- [ ] OAuth Callback
- [ ] パスワードリセット

- [ ] ファイルアップロード
- [ ] ファイル削除

- [ ] サーバー掲載API
- [ ] 管理者API

管理者API

このあたりを「ログインしてるからOK」ではなく、**「このユーザーが、このリソースに、この操作をする権限を持っているか」**という単位で確認する。

合格条件

「攻撃されない」ではなく、

«侵入されても、他ユーザーのデータを大量取得・改ざん・削除できない»

状態を目標にする。

さらに、

«漏洩しても被害が限定されるよう、保存する個人情報そのものを減らす。»

合格条件

「攻撃されない」ではなく、

«侵入されても、他ユーザーのデータを大量取得・改ざん・削除できない»

状態を目標にする。

さらに、

«漏洩しても被害が限定されるよう、保存する個人情報そのものを減らす。»

この2つをLinkordのセキュリティ設計の基本方針とする。
