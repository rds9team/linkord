# Linkord セキュリティ仕様

## 1. 基本方針

- 秘密情報をクライアントへ送らない
- OAuth2トークンをログに出さない
- ユーザー入力を信用しない
- 権限確認をサーバー側で行う
- 管理者操作を監査ログに残す
- 外部API障害時も安全側に倒す
- 自動判定だけで即時BANしない

## 2. OAuth2

- OAuth2のstateを生成・検証する
- CSRF対策を行う
- callbackのcodeを一度だけ使用する
- redirect_uriを固定する
- 必要最小限のスコープのみ要求する
- Discordアクセストークンを不要に長期保存しない
- OAuth2エラー時に安全なエラー画面を表示する

## 3. セッション

- HttpOnly Cookieを使用する
- Secure属性を本番で有効にする
- SameSite属性を設定する
- セッションIDを推測不能にする
- ログアウト時にセッションを破棄する
- セッション固定攻撃を防ぐ
- 長期間使われていないセッションを無効化する

## 4. 権限管理

以下を明確に分ける。

- 未ログインユーザー
- 一般ユーザー
- サーバー所有者
- Team
- 管理者
- Founder

サーバー編集、メディア削除、通報処理、バッジ付与は必ずサーバー側で権限確認する。

## 5. XSS対策

- ユーザー入力をHTMLとして直接出力しない
- 自己紹介をサニタイズする
- URLを許可プロトコル制にする
- `javascript:`を拒否する
- `data:` URLを必要な場合以外拒否する
- カスタムHTMLを提供しない
- カスタムCSSを提供しない
- Markdownを使用する場合は安全な記法だけ許可する

許可するURLプロトコル：

```text
https
http
```

## 6. SSRF対策

外部URLをサーバーから取得する場合：

- localhostを拒否する
- プライベートIPを拒否する
- metadata endpointを拒否する
- リダイレクト先も検証する
- 許可するURLの用途を限定する
- タイムアウトを設定する
- レスポンスサイズを制限する

## 7. ファイルアップロード

- Content-Typeを信用しない
- マジックナンバーを確認する
- 拡張子を正規化する
- ファイル名をそのまま保存しない
- ランダム名またはSHA-256名を使用する
- ファイルサイズを制限する
- 動画の長さを制限する
- 音声の長さを制限する
- 実行可能ファイルを拒否する
- SVGは原則拒否または安全化する
- 保存先を実行可能なWebルートから分離する
- 管理者が削除できるようにする

## 8. レート制限

以下にレート制限を設定する。

- ログイン試行
- プロフィール編集
- メディアアップロード
- サーバー登録
- ブースト
- フォロー
- 通報
- PlayHive API取得
- Lanyard取得
- 管理者API

ブーストは以下の組み合わせで制限する。

```text
user_id + server_id + 1時間
```

IPだけを唯一の制限要素にしない。

## 9. ランキング不正対策

- 自分自身のアクセスを除外する
- 同一ユーザーの短時間連続アクセスをまとめる
- 同一IPからの異常な連続アクセスを抑制する
- User-Agentだけを信用しない
- 急激な増加を管理者へ警告する
- 不正なアクセス数を後から無効化できるようにする

## 10. 外部API

- APIキーや秘密情報を環境変数に保存する
- レスポンスをそのままHTMLに埋め込まない
- タイムアウトを設定する
- リトライ回数を制限する
- レート制限を尊重する
- 外部APIのエラー詳細をユーザーへ露出しない
- キャッシュを利用する
- API停止時のフォールバックを用意する

## 11. PayPay支援リンク

- 支援リンクをソースコードに直書きしない
- 環境変数または管理画面から変更可能にする
- 支援は任意であることを表示する
- 支援しなくても基本機能を利用可能にする
- 支援額を推測・公開しない
- 有効期限切れのリンクに対応する

## 12. 個人データ

保存する情報はサービス提供に必要な最小限にする。

保存する情報：

- DiscordユーザーID
- プロフィール情報
- ユーザーが登録したリンク
- ユーザーがアップロードしたメディア
- サービス利用に必要なログ

保存しない情報：

- プロフィール訪問者の個人履歴
- 不要なDiscordフレンド情報
- 不要なサーバーメンバー情報
- 不要なOAuth2トークン

## 13. 退会・削除

ユーザーは以下を削除できる。

- プロフィール
- メディア
- サーバー登録
- フォロー情報
- Minecraft連携
- アカウント全体

削除処理は以下を行う。

- DB上の個人データ削除または匿名化
- メディアファイル削除
- セッション無効化
- キャッシュ削除
- 検索結果から除外
- ランキングから除外

## 14. 管理者セキュリティ

- 管理者アカウントを限定する
- 管理画面へのアクセスを制限する
- 管理者操作を監査ログに記録する
- バッジ付与・ユーザー停止・通報処理を記録する
- 管理者用APIに追加レート制限を設定する
- 管理者権限をDB上で検証する

## 15. ログ

ログに以下を含めない。

- OAuth2アクセストークン
- セッションCookie
- PayPay管理情報
- パスワード
- 不要な個人情報
- 完全な認証ヘッダー

記録するもの：

- エラー種別
- リクエストID
- 対象API
- 内部ユーザーID
- 外部APIの成功・失敗
- 管理者操作
- 不正アクセス警告

## 16. GuardLLM(ローカルホスト)

Guardは補助的な判定システムとして扱う。

判定カテゴリ：

- normal
- spam
- phishing
- nsfw
- scam
- harassment
- illegal

Guardだけで自動BANしない。

基本フロー：

```text
投稿
  ↓
ルールベース検査
  ↓
ローカルLLM判定
  ↓
通常公開または管理者警告
  ↓
管理者が確認
```

## 17. バックアップ

- DBを定期バックアップする
- アップロードファイルを定期バックアップする
- バックアップの復元テストを行う
- バックアップにもアクセス制限を設定する
- 秘密情報をバックアップへ不用意に含めない
